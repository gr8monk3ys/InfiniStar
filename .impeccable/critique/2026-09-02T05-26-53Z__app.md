## Priority Issues

- [P0] /sign-in renders a plausible, empty, unusable card. AuthShell has no loading boundary and no error state; a Clerk outage, blocked script or ad blocker yields the same screen in production. Pre-existing. Fix: client boundary + labelled skeleton with aria-busy, timeout -> role="alert" error with retry, no operator copy; add privacy/terms links.
- [P0] Mobile bottom nav: four links with no accessible name. MobileFooter never passes `label`; MobileItem renders only an aria-hidden icon; no aria-current. Below lg this is the only nav and logout is one of the four glyphs. Pre-existing (verified against HEAD). WCAG 2.4.4 / 4.1.2.
- [P1] .glass does not blur. backdrop-filter computes to `none` in both themes while the translucent background applies; headlines and prices read through the nav on every scrolled route. Pre-existing, unchanged from HEAD. Fix: debug @layer ordering or make the header opaque and keep glass for chat-preview cards.
- [P1] Pricing invents social proof and hides the real limit. Hardcoded "Most Popular" badge violates the no-placeholder-proof rule; PRO says "fair use cap applies" while AI_PRO_MONTHLY_COST_CAP_CENTS=800 is stated nowhere; TokenUsageDisplay says "Unlimited". Also text-green-500 checks on Free break the second-hue rule.
- [P1] Home page has no error state. app/(marketing)/page.tsx catches the Prisma failure with console.error and renders "the marketplace is still warming up" — an outage presented as a product state, on the page carrying every acquisition path. /pricing has no try/catch at all.

## Questions

1. The home page sells the creator product while PRODUCT.md names the chatter as primary. If supply is the bottleneck, say so in the positioning rather than hedging.
2. DESIGN.md documents named rules that the shipped build breaks in six places. Each is checkable in <50 lines of CI. What would it cost to make the design system fail the build the way TypeScript does?
3. The exit flow (account deletion) got a grace period, typed confirmation and support off-ramp. The mature-content gate is a checkbox styled identically to a visibility toggle. Why did the exit get the most care?
